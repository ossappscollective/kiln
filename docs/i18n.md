# Localisation (i18n)

Kiln's web app speaks English, French, Spanish and German, and is built so a translator can add a language without touching code.
This page is for people who write code (and agents converting screens). Translators read [translating.md](translating.md); the terms to
use per language are in [i18n-glossary.md](i18n-glossary.md); the decision is [ADR 0044](adr/0044-localisation.md).

## How it works

- **Catalogs** are JSON files: `apps/web/locales/<namespace>/<language>.json`, for example `locales/shell/fr.json`. One file per namespace
  per language. `en.json` is the source: it is where a string is born. The other files are translated by Weblate.
- Files are **flat**: `"card.title": "Reviews"`. Keys are dot-separated camelCase ids (`empty.noApps`, `delta.up_one`). Values are text with
  `{{name}}` placeholders. Plurals are separate keys with a CLDR suffix: `_one`, `_other` (and `_zero`, `_two`, `_few`, `_many` where a
  language has them). This is the "i18next JSON v4" layout, read by a small runtime of our own (about 300 lines). There is no i18n library.
- **Files are written one way** (sorted keys, 2 spaces, final newline) so Weblate and humans produce the same bytes. `pnpm i18n:fix` rewrites them.
- **Runtime** (`apps/web/src/lib/i18n/`): `t('ns:key', params)`, a `<T>` component for messages with a link or emphasis, formatting helpers
  (`format.ts`), the language picker state (`i18n.svelte.ts`). English is bundled and always answers. Another language is fetched (one small
  chunk per namespace) **before the app mounts**, so the first paint is never a row of keys. If the fetch takes over 4 seconds the app mounts in
  English and switches when the files arrive.
- **Which language**: `?lang=fr` in the address (this visit only, never saved; `?lang=pseudo` for the pseudo-locale), else the saved choice
  (`localStorage` key `kiln.locale`), else the best match of `navigator.languages` (`fr-CA` gives `fr`), else English. The choice sets
  `<html lang>` and `dir`.
- **A missing string never breaks the screen**: a key missing from the active language is read from English; a key missing everywhere shows
  the key (`shell:nav.nope`) and, in development, logs once.

## Convert a component: the recipe

1. Pick the namespace of the area you own (table below) and open `apps/web/locales/<ns>/en.json` (create it if it does not exist).
2. Replace each visible string with `t('<ns>:<semantic.key>')` and add the key to `en.json` with the English text. Do the same for `title`,
   `aria-label`, `placeholder` and `alt`.
3. Import: `import { t } from '../lib/i18n/t.ts';` (relative path as everywhere in this repo). In a template: `{t('shell:nav.allApps')}`.
4. A count: write the plural keys (`badge.unanswered_one`, `badge.unanswered_other`) and call `t('ns:badge.unanswered', { count: n })`.
5. A message with a link or bold text: one message with `<link>…</link>` tags and the `<T>` component (see "Rich text").
6. Dates, numbers, money, lists, sizes: use the helpers of `lib/i18n/format.ts`, never `toFixed`, `toLocaleString('en')` or hand-built text.
7. Add the same keys to `fr.json`, `es.json`, `de.json` **only if you are fluent and keep to the glossary**; otherwise leave them out (they
   fall back to English and Weblate asks translators for them).
8. Run `pnpm i18n:fix && pnpm i18n:check`, then `pnpm --filter @kiln/web test`. Look at the screen with `?lang=pseudo`: any plain ASCII text
   is still hard-coded.

```svelte
<script lang="ts">
  import { t } from '../../lib/i18n/t.ts';
  let { count }: { count: number } = $props();
</script>

<h2>{t('reviews:inbox.title')}</h2>
<button aria-label={t('reviews:inbox.close')} title={t('reviews:inbox.close')}>…</button>
<p>{t('reviews:inbox.unanswered', { count })}</p>
```

```json
{
  "inbox.close": "Close the inbox",
  "inbox.title": "Reviews inbox",
  "inbox.unanswered_one": "{{count}} unanswered review",
  "inbox.unanswered_other": "{{count}} unanswered reviews"
}
```

In a `.ts` lib module (testable with `node --test`) do the same with `import { t } from './i18n/t.ts';`.

## Rules for conversion (read before you start)

1. **One namespace file set per area.** You edit `locales/<your ns>/*.json` and the components and lib modules of your area. Never edit another
   area's catalog; if you need a string that exists elsewhere, add your own key (a little duplication is cheaper than coupling).
   Shared words ("Save", "Cancel") live in `common` and may be reused by everyone; adding to `common` is a small additive edit on a fresh read.
2. **Never concatenate translated fragments.** `t('a') + ' ' + t('b')` and `${n} ${t('apps')}` cannot be translated: word order and grammar
   differ. Make one message with placeholders: `"summary": "{{done}} of {{total}} steps done"`.
3. **No sentence fragments in code.** No `count === 1 ? 'app' : 'apps'`, no `'s'` suffixes, no strings assembled from parts. Plurals are
   `_one`/`_other` keys with `{{count}}`; the language decides which form.
4. **Keys are semantic, not positional.** `empty.noApps`, `form.nameRequired` — not `text1`, `label3`, `Save changes`. Name what the string
   is for. Keep a key's meaning stable: when the English text changes meaning, change the key (the old translations would be wrong).
5. **No HTML in messages**, and no `{@html}`. A link or emphasis uses the tags below and `<T>`.
6. **Punctuation belongs inside the message.** "Saved." and "Name:" are translated with their dot and colon (French puts a space before `:` and `?`).
   Do not add `:`, `.`, `…` or `?` in code.
7. **Plurals use `{{count}}`, not conditionals.** If a sentence has two numbers, pick the one the grammar follows as `count` and pass the
   other under another name (`t('common:validation.passwordTooShort', { count: min, length })`).
8. **`aria-label`, `title`, `placeholder`, `alt`, toast text, document title, and error text are all translatable.**
9. **Do not call `t()` at module top level.** It would run once, in whatever language was active. In a module that builds a list once (the
   nav, a table of columns), store the key with `k('ns:key')` and translate where it is drawn: `t(item.labelKey)`.
   Strings kept in `$state` have the same problem: keep the key, translate in the template.
10. **Keys are literals.** `t('reviews:status.open')`, never `t(`reviews:status.${status}`)`. For a value that decides the message, keep a typed
    map of literal keys: `const keys = { open: k('reviews:status.open'), closed: k('reviews:status.closed') }` then `t(keys[status])`.
    `pnpm i18n:check` reads `t('…')`, `k('…')` and `<T key="…">` statically; `t(map[x])` is accepted, a built key is a warning.
11. **Do not translate**: product and store names (see the glossary), code, URLs, file names, identifiers, values from the server that are data
    (app names, review text), and the languages' own names in the picker.
12. **Error codes from the server** are translated in the `errors` namespace by key (the server work defines the codes): the web side maps
    `code` to `errors:<code>` and falls back to the server's English `message`.
13. **Dates, numbers, money**: only through `lib/i18n/format.ts`. Money is never converted between currencies.
14. **Tests**: a test that asserts English text keeps working (the test runner preloads the English catalogs). Prefer asserting on keys or on
    behaviour; do not assert on other languages except in `lib/i18n`.
15. **Weblate owns the other languages.** If you add French, Spanish or German text by hand, you must be fluent, follow the glossary, and keep
    the `{{placeholders}}` and tags exactly; `pnpm i18n:check` rejects a changed placeholder set. Never machine-translate without saying so.

## API

```ts
import { t, tParts, k, currentLocale } from '../lib/i18n/t.ts';       // plain TS, works in node --test
import { i18n, setLocale, initI18n, pickerLocales } from '../lib/i18n/i18n.svelte.ts';  // reactive (runes)
import { formatDate, formatNumber, formatCurrency /* … */ } from '../lib/i18n/format.ts';
import T from '../components/ui/T.svelte';
```

| API | What it does |
| --- | --- |
| `t('ns:key', params?)` | The message in the active language. `{{name}}` is replaced by `params.name`. `params.count` (a number) picks the plural form with `Intl.PluralRules` of the active language (`key_<category>`, then `key_other`, then `key`) and is written with the language's digit grouping. Falls back to English, then to the key. Reactive: call it in a template, `$derived` or `$effect`. |
| `k('ns:key')` | Returns the key unchanged. Marks a literal key in a typed map so the tooling sees it. |
| `<T key="ns:key" params={…} tags={{ link }} />` | A message with `<link>…</link>`, `<strong>`, `<em>`, `<code>`. See below. |
| `i18n.locale` | The active language code, reactive (`'fr'`). `i18n.info` is its `{ code, name, dir, htmlLang }`; `i18n.switching` is true while files load. |
| `setLocale(code, { persist? })` | Loads the language, makes it active, saves it in `kiln.locale` (not with `persist: false`). Resolves to whether it is active. |
| `availableLocales` | `en`, `fr`, `es`, `de` with their native names (`English`, `Français`, `Español`, `Deutsch`). `pickerLocales` adds `pseudo` in development builds only. |
| `initI18n()` | Called once by `main.ts` before the app mounts. Never rejects. |

### Plurals

```json
"badge.attention_one": "{{count}} app needs attention",
"badge.attention_other": "{{count}} apps need attention"
```

English needs `_one` and `_other`. Other languages use the forms CLDR gives them: French and Spanish `one, many, other` (`many` is for
millions: "1 million de …"), German `one, other`, Arabic `zero, one, two, few, many, other`. Weblate creates the forms each language needs;
an empty form is "not translated yet" and falls back to `_other`, then to English. In French, `one` covers 0 and 1: "0 avis", "1 avis".

### Rich text: a link or emphasis inside a sentence

Translators see one message with tags, never HTML:

```json
"setup.help": "Need a key? Read <link>the credentials guide</link> and keep it <strong>secret</strong>."
```

```svelte
<script lang="ts">
  import T from '../ui/T.svelte';
</script>

<p><T key="credentials:setup.help" tags={{ link }} /></p>

{#snippet link(text)}<a href="#/credentials" class="link">{text}</a>{/snippet}
```

- Allowed tags: `link`, `link2`, `link3` (you supply a snippet that gets the text inside), and `strong`, `em`, `code` (rendered for you).
  The tag set, closing, no nesting and "the same tags in every language" are enforced by `pnpm i18n:check`.
- `<T>` renders text nodes and your snippets. It never uses `{@html}`; a value passed in `params` can never create a tag.
- Do not call `t()` on a message with tags (the check fails it).
- Several links in one message: `<link>` and `<link2>`, each with its own snippet in `tags`.

## Formatting

All helpers are in `lib/i18n/format.ts`, take the active language by default (so a call in a template re-renders when the language
changes), and accept `{ locale }` to force one. They return `''` for a value that cannot be formatted.

| Helper | Example (en / fr) |
| --- | --- |
| `formatNumber(12345.6)` | `12,345.6` / `12 345,6` |
| `formatPercent(0.256)` | `26%` / `26 %` |
| `formatCompact(12900)` | `12.9K` / `12,9 k` |
| `formatCurrency(1234.5, 'USD')` (major units) | `$1,234.50` / `1 234,50 $US` |
| `formatMinorUnits('499', 'USD')` (store prices: minor units as digits) | `$4.99` |
| `formatDate(at)`, `formatDateTime(at)`, `formatTime(at)` | `Nov 21, 2026` / `21 nov. 2026` |
| `formatRelativeTime(at)` | `5 minutes ago` / `il y a 5 minutes` |
| `formatList(['a','b','c'])` | `a, b, and c` / `a, b et c` |
| `formatBytes(1536)` | `1.5 kB` / `1,5 ko` |
| `formatDuration(3725000)` | `1 hr 2 min` |
| `formatDisplayName('de-DE', 'language')` | `German (Germany)` / `allemand (Allemagne)` |

**Money.** The app holds money in two shapes: analytics figures are numbers in major units (use `formatCurrency`); store prices are
strings of minor units (`Price.amount` `"499"` is 4.99 USD; use `formatMinorUnits`, which moves the decimal point in the text and never
does floating-point arithmetic). A missing or unknown currency is written as its code. Nothing is converted between currencies.

**Which tag Intl gets.** The app language alone is too coarse (`en` is the US, the UK, India…), so when the browser's language list names the
same language with a region (`en-GB`, `de-CH`), that tag is used for numbers, dates and currency placement (`formatLocaleFor` in
`locales.ts`). Otherwise the app language. The pseudo-locale formats as English.

**Default currency.** `defaultCurrency` (lib/analytics/currency.ts) keeps using the **browser's** locale region, not the app language:
the language says what a person reads, the region says where they are. Someone in the US who picks French still has USD as the default.

**Time zone** stays the viewer's own (`Intl` default); `browserTimeZone()` in `lib/alerts/alerts.ts` reads the zone, not the language, and is not converted.

## Pseudo-locale

`?lang=pseudo` (or `localStorage.setItem('kiln.locale', 'pseudo')`, then reload) shows every message from English with accents, inside
brackets and about 30 percent longer: `Reviews inbox` becomes `[Ŕéṽîéŵš îñƀöẋ ~~~~]`. Use it to:

- find hard-coded strings (they stay plain ASCII, and show without brackets),
- find clipped layouts (a missing `]` means the text is cut; German and French run 20-40 percent longer),
- check that nothing builds text from fragments.

It is offered in the language picker only in development builds (`pickerLocales`). It needs no files.

## Language picker and where the choice lives

A **Language** select is in the account menu (every role), on the sign-in and setup pages (small select under the card, so a signed-out
person can choose), and as a card at the bottom of Settings, General (`components/ui/LanguageSelect.svelte`,
`components/settings/LanguageSettings.svelte`). Each option is written in its own language and carries its own `lang` attribute; the
label is always visible.

The choice is saved **in this browser** (`localStorage` `kiln.locale`), like the theme, with no server round-trip, so it works before sign-in
and on the desktop shell. Decision: it stays a per-browser preference for now. If people want it to follow them across browsers, add a
`language` field to the user profile later: send it on sign-in, apply it as the initial value when `kiln.locale` is not set, and keep
`kiln.locale` as the signed-out fallback. The server-side messages that people read (emails, alerts) need a language anyway; that work is
the server's and will decide it.

## Tooling

```
pnpm i18n:check            # validate catalogs and the keys used in the source; exit 1 on errors
pnpm i18n:check --strict   # also fail on English keys nothing uses
pnpm i18n:fix              # rewrite every catalog: sorted keys, 2 spaces, final newline
pnpm i18n:scan             # hard-coded string report per namespace (never a gate); --files, --items, --json
```

`pnpm test` runs the check (`apps/web/src/lib/i18n/catalogs.test.ts`), so a PR with a broken catalog or an unknown key fails.

**check** fails on: invalid JSON; a file not in the canonical layout; nested or non-string values; a key that is not a valid id; an empty English
value; a language not registered in `availableLocales`; a non-English key English does not have (orphan), or plural in one and plain in the
other; a plural suffix the language does not use (`Intl.PluralRules(lang).resolvedOptions().pluralCategories`: English `one, other`; French and
Spanish `one, many, other`; German `one, other`); placeholders or tags that differ from English (a plain message must match exactly; a plural form
must have the placeholders of the English form of the same category, or of `other`, and none English's group lacks); any HTML, an entity, or a tag
other than `link`, `link2`, `link3`, `strong`, `em`, `code` (closed, not nested); a `t('ns:key')`, `k('ns:key')` or `<T key="ns:key">` whose key
is not in `locales/<ns>/en.json` (a plural base such as `badge.attention` counts); and `t()` on a message that holds tags.
It **warns** about keys built at run time, and **reports** unused English keys (an error with `--strict`) and, per language, how many
messages are still untranslated (a percentage; never a failure: Weblate fills them).

**scan** is a heuristic for progress: text nodes, `title`/`aria-label`/`placeholder`/`alt` and common component props (`title`, `label`,
`description`, `hint`, …) with a plain string, and literals that read like text in `{…}` expressions, in `.svelte` files; and sentence-like
string literals (two words or more) in `lib/*.ts`. It skips `<code>`, `<kbd>`, `<pre>`, `<svg>`, comments and message keys. Expect a few false
positives and a few misses. Run it to see progress; a file at 0 is not proof, `?lang=pseudo` is.

## Testing

- `pnpm --filter @kiln/web test` preloads the English catalogs (`node --import ./src/lib/i18n/test-setup.ts --test …`), so lib modules that call
  `t()` return real English text in tests. To run one file: `node --import ./src/lib/i18n/test-setup.ts --test src/lib/foo.test.ts`
  (from `apps/web`). Without the flag a converted module returns its keys.
- `useLocale('fr')` (from `lib/i18n/test-setup.ts`) switches a test file to another language; `useLocale('en')` restores it.
- `lib/i18n/*.test.ts` cover the runtime (interpolation, plural selection per language, fallback, pseudo-locale), the formatting helpers and the check.

## Not done here / open

- Server messages shown to people, the desktop menus and the conversion of the other 300 components are separate work (see the plan above).
- `<html lang>` follows the choice; `index.html`'s static `<title>` and meta description stay English (the title is replaced by the shell once it mounts).
- There is no "Automatic" entry in the picker to forget the choice and go back to the browser's language; `saveLocalePref(null)` exists for it.
- Right-to-left languages are plumbed (`dir` is set) but the layout uses physical `left`/`right` in places; do it with the first RTL language.
